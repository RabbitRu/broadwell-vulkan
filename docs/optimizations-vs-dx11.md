# Производительность: Vulkan против DX11 на Iris 6100

Что измерено, какие идеи уже проверены и как мерить. **Перед новым опытом
найти его в реестре (раздел 1):** большинство очевидных идей уже проверено.
Допустимы только универсальные исправления драйвера (решение пользователя).
Состояние на 2026-11-21.

## 0. Итоги

**The Talos Principle (этап закрыт).** Vulkan 70–83 FPS против 79–87 у DX11
(встроенный бенчмарк, 640×480). Кадр под обоими API задаёт главный поток игры
(87–90 % занят). Драйвер обходится ему дешевле драйвера Intel с рантаймом
D3D11 (2,35 против 3,37 мс на кадр), а код самой игры под Vulkan идёт на
2,27 мс дольше. Причина — путь Vulkan игры: каждый кадр очищает и
перестраивает карты теней с альфа-тестом (3,7 млн вызовов FS на карту против
7 тыс. у DX11). GPU занят 81–91 % против 73–77 %, и из-за общего бюджета
питания CPU работает на 4–19 % медленнее. Без построения теней
(`+shb_bUpdateShadows 0`) Vulkan 114–124 против 114–117 у DX11 (F6): весь
разрыв — тени, драйвер разрыва не даёт.

**Dota 2 (текущий этап).** Vulkan 23,2–24,7 FPS против 26,0–26,9 у DX11
(timedemo, `run-dota.ps1`). Замеры 2026-11-21:
- **Кадр упирается в CPU кода игры.** Игра отправляет весь кадр одним
  `vkQueueSubmit` в конце работы CPU. GPU выполняет его за ~22–25 мс плюс
  ~2,4 мс копии вывода и ~14 мс на кадр простаивает. Время GPU на кадр под
  обоими API одинаковое (~29 мс: загрузка 3D 72 % при 24,7 FPS против 76 % при
  26,1).
- Главный поток игры занят 88 % под обоими API: 35,8 против 33,8 мс CPU на
  кадр. Его код `client.dll` идёт одинаково (17,0 мс). Под Vulkan больше
  `particles` (+0,6) и `rendersystemvulkan` против `rendersystemdx11` (+0,55),
  и он дольше ждёт (+1 мс).
- Рабочий поток игры: 22,6 против 19,6 мс на кадр. Медленнее почти все модули
  (particles +0,95, client +0,83, rendersystem +0,49, materialsystem2 +0,33,
  scenesystem +0,32), кроме panorama.
- **Драйвер на критическом пути почти не стоит.** На главном потоке — 0,3 %
  выборок. Запись команд идёт на потоке отрисовки игры: драйвер ~2,8 мс на
  кадр, поток занят 18 % и в основном ждёт. Наш поток очереди занят ~3 % (вызов
  ядра с выводом ~1 мс CPU). Под DX11 поток драйвера Intel тратит 16 мс на
  кадр (42 %), и всё равно DX11 быстрее. Всего CPU игры: Vulkan 171 %, DX11
  188 % логического CPU. С `HASVK_WDDM_PROFILE_PASSES` (драйвер на 10–15 %
  дороже) медиана кадра растёт лишь на ~0,7 мс.
- Значит, оставшиеся ~3 мс на кадр — путь Vulkan самой игры и замедление её
  рабочего потока. Причина второго (соседний логический процессор, память,
  кэш) не найдена (G6–G8 в реестре).

## 2. Ключевые замеры

**Talos, главный поток, мс на кадр** (`rip-compare.py`, адреса кода без
обхода стеков, DX11 84,3 FPS / Vulkan 73,5):

| | DX11 | Vulkan |
|---|---|---|
| Код игры | 6,19 | 8,46 (путь Vulkan игры 1,43 мс, общий код ×1,27) |
| Драйвер (`igd10iumd64` + `d3d11` / наш) | 2,75 | 2,15 |
| Вызовы ядра (`win32u`) | 0,62 | 0,20 |
| `ntdll` (ожидания) | 2,10 | 2,48 |

**Talos, GPU по проходам:** две карты теней 1536² — 2,4 мс у DX11, ~5,2 у
Vulkan (работу заказывает игра); основной проход 3,5 против ~2,9; предпроход
1,7 против ~1,1; мелкие проходы вровень.

**Микротесты против D3D11 Intel:** VS с `texelFetch` 1,00; пустой VS
0,89–0,94; сэмплер 0,95–0,98; FMA 0,84; заливка глубины с `discard` 0,96–1,0;
стоимость draw 0,11 против 0,08 мкс.

**Dota, потоки** (`run-dota.ps1 -Sample`, % логического CPU): Vulkan — главный
88, рабочий 55, отрисовка 18, очередь драйвера ~3; DX11 — главный 89, рабочий
51, отрисовка с драйвером Intel 42. Частота CPU ~2,9–3,0 ГГц под обоими, флаги
ограничения 0. Разделы игры (`timedemo_profile.csv`, мс): `Client Rendering`
24,8 против 21,2, `Frame Boundary` 10,8 против 9,1; `Client Simulation`
гуляет на ±1 мс между прогонами одного API.

## 3. Как мерить

Из корня проекта; `Remove-Item Env:PYTHONHOME` перед сборкой. Сборка:
`tools\build-icd.ps1` (или `build-mesa-compiler.ps1 -DebugInfo`, затем
`build-icd.ps1 -SkipBuild` — символы для `rip_sampler` и lldb).
`tools\build-probes.ps1` — пробы и инструменты в `build\probes`.

```powershell
# Dota (всегда -insecure; результат — build\dota\<Tag>.*)
.\tools\run-dota.ps1 -Api Vulkan -Tag v1
.\tools\run-dota.ps1 -Api Direct3D11 -Tag d1
.\tools\run-dota.ps1 -Tag s1 -Sample                                 # потоки, частота, GPU
.\tools\run-dota.ps1 -Tag r1 -RipModule vulkan_hasvk_wddm.dll        # стеки
$env:RIP_NOWALK='1'; $env:RIP_RVAS='25'; .\tools\run-dota.ps1 -Tag a1 -RipModule vulkan_hasvk_wddm.dll  # адреса, без замедления
.\tools\run-dota.ps1 -Tag t1 -Start 30000 -End 31500 -Env "HASVK_WDDM_TIMELINE=<путь без кириллицы>.csv"
# Talos (Steam под аккаунтом, которому принадлежит игра; иначе падение в ntdll на обоих API)
.\tools\run-talos.ps1 -Api Vulkan -Tag v1      # -Sample, -RipModule, -D3D11Proxy build\probes\d3d11-proxy\d3d11.dll
# разбор
.\.tools\python\python.exe -I tools\timeline-report.py <csv> [--talos-log ...] [--slow-detail]
.\.tools\python\python.exe -I tools\rip-compare.py <dx.rip.txt> <FPS> <vk.rip.txt> <FPS>
.\.tools\python\python.exe -I tools\talos-sections.py --since 2026-11-19T20:00
# стенд записи команд: снимок прохода и повтор без отправки
.\tools\run-talos.ps1 -Tag cap -Env "HASVK_WDDM_PROFILE_PASSES=1,HASVK_WDDM_CAPTURE_DIR=$PWD\build\talos\pass3,HASVK_WDDM_CAPTURE_PASS=1536"
$env:REPLAY_RECORD_ONLY='20000'; .\build\probes\replay_pass_probe.exe build\talos\pass3
# микротесты (пары Vulkan / D3D11): depth_fill, flops, sample, vs_fetch, cpu_map_probe, gpu_freq_monitor
```

- `HASVK_WDDM_PROFILE_PASSES=1` — время GPU по проходам, вызовы ядра, медленные
  кадры с причинами (замедляет на 10–15 %); `HASVK_WDDM_STATS=1` — объём
  команд и память драйвера; `HASVK_WDDM_PROFILE_DRAWS=1` — время каждого draw.
- `run-dota.ps1 -Sample/-RipModule` и `run-talos.ps1` запускают
  `tools/talos-window.ps1`: он ждёт маркер в журнале игры (Dota —
  `DOTABaseGameMode::Spawn()` + 25 с, Talos — «Starting automated benchmark»
  + 3 с) и мерит окно.
- A/B вариантов компилятора — через переменную, входящую в UUID кэша
  (`INTEL_DEBUG`); правка кода меняет UUID сама.
- CTS: `.\tools\run-cts.ps1 -Case 'dEQP-VK.…' -Name x -Jobs 2` (DLL из
  `build\icd`).

## 4. Подводные камни

- **Разброс и прогрев.** Прогоны подряд становятся медленнее (Dota Vulkan
  24,7 → 23,2, DX11 26,9 → 26,0): сравнивать только чередованием в одной серии,
  не меньше трёх пар. Первый прогон после новой сборки холодный (компиляция
  конвейеров) — не учитывать. Фон: HWiNFO ~8 %, Steam, само приложение Claude
  — одинаково для обоих API.
- Время CPU потоков — только `QueryThreadCycleTime`: `GetThreadTimes` считает
  по тикам таймера и занижал главный поток в 3 раза.
- Счётчики PDH в процессе с русским интерфейсом не находятся по английским
  именам: нужен `SetThreadUILanguage(0x409)` (сделано в `talos-window.ps1`); в
  `Start-Job` счётчиков процессора нет.
- `rip_sampler` с обходом стеков замедляет игру на 8–12 % (доли сравнимы,
  FPS — нет); с `RIP_NOWALK=1` — почти не замедляет.
- Dota: значения консольных переменных не узнать ни `+cvarlist` в командной
  строке (срабатывает до готовности консоли, вывода нет), ни через
  `-testscript_inline` (понимает только `Test_*` и `quit`); имена и описания
  есть строками в `rendersystemvulkan.dll`, `particles.dll`. Переменные из
  командной строки игра сохраняет в конфиги — `run-dota.ps1` их возвращает.
- Путь журнала кадра — без кириллицы (файл пишется через ANSI-путь; в
  scratchpad или `C:\...`).
- Микротесты GPU короче ~1 с идут на холодной частоте GPU: брать лучшее из
  250–400 повторов.
- Не запускать одновременно CTS, игры и сборку (`build-icd.ps1` перезаписывает
  DLL в `build\icd`; сборка грузит CPU и портит замеры).
- После изменения: `test-all`; для синхронизации, глубины, памяти, конвейера —
  срезы CTS по затронутым группам; изменения состояния GPU — с учётом
  `roadmap.md`, раздел 3.
