# Закрытый интерфейс Intel, от которого зависит порт

Всё, что ICD передаёт драйверу ядра Intel `20.19.15.5171` сверх документированных
структур D3DKMT. Документированы только сами вызовы и обёртки (`d3dkmthk.h`);
приватные данные внутри них Intel не описывает. Каждое значение ниже снято
трассировкой драйверов Intel из того же пакета и проверено пробой на железе.

## Защита от другого драйвера

`hasvk::wddm::Device` создаёт устройство только для адаптера `8086:162b` с версией
UMD-драйвера ровно `20.19.15.5171` (`supported_driver`, `KMTQAITYPE_UMD_DRIVER_VERSION`).
Иначе `enumerate()` в `anv_wddm_device.c` не возвращает ни одного физического
устройства: загрузчик Vulkan пропускает ICD, приложение видит другие GPU, ничего не
отправляется в ядро с непроверенными данными.

## Что именно мы задаём

| Данные | Где в коде | Откуда взято | Чем проверяется |
|---|---|---|---|
| Описатель линейного выделения, 1096 байт | `linear_metadata()`, `native/src/intel_2019_profile.cpp` | побайтно с выделений состояния Intel UMD (`gpu-probe`, `KernelTrace.cs`) | `tools/test-native.ps1`, все пробы ICD |
| Описатель поверхности окна, 1096 байт | `window_surface_metadata()` | поверхность, которую `dwmapi` создаёт через D3D11 для OpenGL-драйвера (`tools/trace-gl-present.ps1`) | `tools/test-present-redirect.ps1`, `vkcube` |
| Данные рантайма поверхности окна, 104 байта | `window_surface_runtime_data()` | та же трасса (формат D3D-рантайма, `DXGI_FORMAT_B8G8R8A8_UNORM`) | то же |
| Заголовок отправки, 80 байт | `command_header_8192()` | трасса отправок Intel UMD; поле 20 проверено только для BO команд 8192 байт | все отправки |
| Приватные данные контекста, 32 байта | `Device::Device` (`presentable_context`) | трасса OpenGL-драйвера: указатель на буфер `0x2cdc` байт, размер, флаг `0x100`; ядро в буфер не пишет | `test-present-redirect.ps1` (без них DWM показывает чёрное), регрессия, CTS |
| Токен перенаправленного вывода | `anv_wddm_present.c` | трасса: `(0x80000000 \| HWND) << 32 \| дескриптор`; совпадает с `updateId` из `dwmapi!DwmpDxGetWindowSharedSurface` | `test-present-redirect.ps1 -Surface dwmapi` |
| `ClientHint` контекста | `Device::Device` | `D3DKMT_CLIENTHINT_VULKAN` (документирован) | — |

### Поля описателя выделения (что известно)

Смещения в байтах, значения 32-битные. Смысл — по сравнению трасс; это не
описание формата Intel GMM.

| Смещение | Линейное | Поверхность окна | Смысл (предположение) |
|---|---|---|---|
| 0x00 | 3 | 3 | версия/класс описателя |
| 0x08 | 6 | 2 | тип ресурса: буфер / 2D |
| 0x0c | 0x155 | 0x17 | формат |
| 0x10 | 8 | 0x20 | бит на элемент |
| 0x14, 0x18, 0x1c | флаги | флаги | использование, тайлинг (ядро меняет 0x18–0x1f при открытии) |
| 0x28 | размер (8 байт) | ширина | |
| 0x30 | — | высота | |
| 0xc0, 0xd0 | — | заполняет ядро: шаг строки и размер | |
| 0x3ac | 0x14330000 | 0x14330000 | сигнатура |

Ядро само выбирает раскладку поверхности окна: Y-тайлинг, шаг
`align(ширина × 4, 128)`, высота кратна 32. Транспорт проверяет это при каждом
создании и отказывается работать, если раскладка другая.

## Что делать на другой версии драйвера

1. Снять заново: `tools/trace-gl-present.ps1` (OpenGL-драйвер: поверхность окна,
   приватные данные контекста, заголовок, токен) и трассу `gpu-probe` (линейные
   выделения).
2. Сравнить с таблицами выше; при совпадении добавить версию в проверку
   `supported_driver`.
3. Прогнать `tools/test-all.ps1`, `test-present-redirect.ps1`,
   `test-kernel-limits.ps1`, выборку CTS.

Чего проверить нельзя без другой версии драйвера: насколько эти значения
стабильны между версиями. Поэтому порт привязан к одной версии.
