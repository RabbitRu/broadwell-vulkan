# Эксперименты без выигрыша и открытые гипотезы

Сводка на 2026-11-19 (пауза по решению пользователя) для этапа 7 roadmap:
Vulkan быстрее DX11 в The Talos Principle. Подробности по каждому пункту — в
`docs/roadmap.md` (этап 7) и `docs/optimizations-vs-dx11.md` (номера 2.x).

Состояние: Vulkan ~79–83 FPS против DX11 ~83–87 в одном состоянии машины
(отношение ~0,92–0,95). По счётчику Windows «GPU Engine Utilization» Vulkan
занимает GPU на ~11,0 мс за кадр, DX11 — на ~8,6 мс (DX11 упирается в CPU
игры, GPU у него простаивает ~26 %).

## 0. Сначала: часть прежних проверок недействительна

До 2026-11-19 `pipelineCacheUUID` драйвера был постоянным
(`HASVK-WDDM-00002`). Ключи кэша конвейеров — хеши шейдеров и параметров
компиляции, а не компилятора, поэтому кэш игры (`VkPipelineCache` Talos,
~1,8 МБ) отдавал новой сборке двоичный код старых. Исправлено: UUID теперь
содержит время записи и размер DLL. Следствие: **любой эксперимент с
изменением генерации кода, проверенный в Talos до этого исправления, мерил
старые шейдеры** и нуждается в повторе:

| Эксперимент | Прежний вывод | Статус |
|---|---|---|
| `INTEL_DEBUG=no8` — без SIMD8 там, где есть SIMD16 (2.2) | «ширина не рычаг», 37,4 против 37,6 FPS | недействителен, повторить |
| VS в режиме vec4 | без выигрыша | недействителен, повторить (vec4-бэкенд из сборки уже убран) |
| Чтение UBO блоком через константный кэш | без выигрыша | недействителен, если менялся код шейдеров |
| Вынос констант из циклов (ELK `combine_constants`) | +1,5 FPS, «шум» | повторён с новым UUID: **−5–8 %**, отменён |

Микротесты (`flops_probe`, `replay_pass_probe` и т. п.) создают конвейеры
без кэша приложения, их выводы это не затрагивает — кроме случаев, когда
стенд запускался уже с файлом `default-cache.bin` (см. раздел 4).

## 2. Сделанное, что не изменило FPS Talos (оставлено как общее улучшение)

| Что | Эффект на измеряемом | FPS Talos |
|---|---|---|

## 3. Открытые гипотезы (по ожидаемому выигрышу)

1. **Повторить проверки генерации кода с действующим UUID** (раздел 0):
   SIMD16 для тяжёлых FS основного прохода (2.2), варианты планировщика ELK.
   Раньше выводы «не рычаг» были получены на старых шейдерах из кэша игры.
   Методика: вариант через переменную окружения, которая входит в UUID
   (иначе кэш отдаёт чужой код), по прогону «холодный + тёплый» на вариант,
   не меньше двух раундов.
2. **Тени — свой путь игры под Vulkan** (3,7 млн вызовов FS на проход против
   7 тыс. у DX11; DX11 не очищает и переиспользует карты). Драйвером
   исправимо только удешевление этой работы: альфа-тест FS ~1 мс на карту
   (2.10), растеризация мелких двусторонних треугольников, VF — 8 вершинных
   элементов на вершину листвы (перенос данных экземпляра из VF в шейдер —
   оценка сверху −0,33 мс на карту). Профили под игру исключены решением
   пользователя.
3. **Частота GPU под Vulkan.** На микротестах результаты Vulkan между
   запусками разбросаны сильнее (выборка 16,4–18,8 Гвыб/с), чем у D3D11
   (19,5–19,8). Гипотеза: промежутки простоя между отправками (ожидание
   завершения через поток завершения) удерживают GPU на более низкой частоте
   (RPS драйвера ядра). Проверка: микротест с непрерывной очередью отправок
   без `vkQueueWaitIdle`; в Talos — время между завершением одной отправки и
   началом следующей.
4. **CPU записи команд** (стенд `REPLAY_RECORD_ONLY`): `vk_dynamic_graphics_state_copy`
   в `vkCmdBindPipeline` (~6 %), `gfx8_cmd_buffer_flush_dynamic_state`
   (~5 %), заполнение surface state динамических UBO в `emit_binding_table`
   (~5 %), `vkCmdBindVertexBuffers2` (~3 %). Каждое — ~1 % потока игры, в FPS
   Talos ниже шума; при упоре в общий бюджет питания CPU+GPU экономия CPU
   может дать частоту GPU.
5. **Медленные кадры:** `CreateAllocation2` теперь сам ждёт очередь подкачки
   ядра (до 90 мс за 5 с при загрузке). Идея: создавать крупные выделения
   заранее/в фоне невозможно без знания приложения; проверить, не помогает ли
   меньший размер блоков пулов или повторное использование только для
   внутренних BO.
6. **Фиксированный путь вершин: 89 % от D3D11** на пустом VS (2.9): разбиение
   URB для VS, размер VUE, режим диспетчеризации VS, настройки `3DSTATE_VF`.
7. **L3/MOCS** (2.7): сравнить конфигурацию L3 hasvk с драйвером Intel.
8. **Перевод барьеров в `PIPE_CONTROL`** (2.6): лишние сбросы кэша глубины
   для переходов не-глубинных изображений. `vlk_bNoBarriers` FPS не меняет,
   поэтому ожидание низкое.

## 4. Не проверено после последних изменений

- 1 % худших кадров с кэшем шейдеров между процессами: в последних тёплых
  прогонах компиляций 0, но отдельного A/B «с файлами кэша / без»
  (`HASVK_WDDM_INTERNAL_CACHE=0`) не было.
- `default-cache.bin` наполняется и CTS (конвейеры без кэша приложения),
  размер ограничен 64 МиБ; при большом файле каждый процесс читает его
  целиком при создании устройства — время запуска не мерилось.
- Проверено перед паузой: CTS `pipeline.monolithic.creation_feedback` (13),
  `creation_cache_control` (17), `cache` (387, каждый второй) — по два раза,
  второй при тёплом `default-cache.bin`: все Pass; в `creation_cache_control`
  одно QualityWarning в обоих проходах (не от файлов кэша). После выборки
  `default-cache.bin` — 1,1 МБ, `internal-cache.bin` — 44 КБ.
- Установленная копия ICD в `C:\Program Files\HasVK-WDDM` — сборка от
  2026-11-18, без изменений этапа 7.

## 5. Методика и подводные камни

- Разброс FPS Talos ±5 %: сравнивать только чередованием сборок в одном
  состоянии машины, не меньше 3+3 прогонов; машина «разогревается» по ходу
  серии (FPS растёт к концу).
- Первый прогон после новой сборки — холодный: игра перекомпилирует все
  конвейеры (461 компиляция, 1 % худших ~7 FPS). Его не учитывать.
- Изменения генерации кода — только с UUID, который их различает (раздел 0).
- Тестовый бот игры иногда завершает уровень через ~2 с («end of game»), в
  том числе до изменений драйвера; `run-talos.ps1` повторяет такой прогон.
- Профилированные прогоны (`HASVK_WDDM_PROFILE_PASSES`) медленнее на 10–15 %;
  FPS сравнивать только без профиля.
- Микротесты GPU короче ~1 с идут на холодной частоте GPU (440–600 МГц
  против ~1 ГГц): сравнивать по длительной нагрузке (250+ запусков).
- Стенд записи команд: `replay_pass_probe` + `REPLAY_RECORD_ONLY=<n>`
  (разброс ~1 %), горячие строки — `rip_sampler` с `RIP_LINES=<n>`.
- CTS-выборка и Talos не запускать одновременно; сборку ICD
  (`build-icd.ps1`) — только когда CTS не держит `build\icd`.
