# Известные отказы и неподдерживаемые группы CTS

Конфигурация: Iris 6100 (8086:162b), драйвер `20.19.15.5171`, Windows, CTS
`vulkan-cts-1.4.5.5`. Список составлен по выборочным прогонам; полный прогон
CTS ещё не выполнялся.

## Ожидаемые отказы (причина установлена, в ICD не исправляется)

| Тест | Результат | Причина |
|---|---|---|
| `dEQP-VK.tessellation.misc_draw.tess_factor_barrier_bug` | `VK_ERROR_DEVICE_LOST` через ~4 с (иногда Pass) | Нагрузка дольше таймаута TDR Windows (2 с), а не зависание. Вершинный шейдер делает ≈6,0·10⁸ `atomicAdd` в одну ячейку (524 288 инстансов × 4 вершины × 36/64 × 512). Измеренная скорость атомиков в один адрес на этой GPU — 287 млн/с (compute, счётчик точный), то есть ≥2,1 с только на атомики. В Linux у i915 нет жёсткого 2-секундного лимита, поэтому upstream этот тест проходит. Менять `TdrDelay` — системная настройка, ICD её не трогает. |
| Следующий за ним тест в том же процессе | `ResourceError` | Устройство потеряно предыдущим тестом; отдельно этот тест проходит. |
| `dEQP-VK.wsi.win32.swapchain.simulate_oom.min_image_count` | `Timeout` (и при лимите 20 мин) | Долгий тест, не ошибка: для 16 конфигураций (1–16 изображений) он отказывает каждому выделению по очереди, около 2300 попыток создать swapchain. Каждая стоит ~0,5 с: изображения и их CPU-буферы — отдельные выделения WDDM. Все 16 конфигураций пройдены без падений и ошибок. |

## Известные ошибки (не исправлены)

Найдены выборками CTS 2026-11-19; есть и в сборке от 2026-11-18, то есть не
вызваны работами по производительности.

| Тест | Результат | Что известно |
|---|---|---|
| `dEQP-VK.subgroups.clustered.compute.subgroupclustered{add,and,or,xor}_i64vec4_requiredsubgroupsize` (4 теста) | Fail | Отказ только при обязательном размере подгруппы 32 (остальные размеры 8–16 и типы i64/i64vec2/i64vec3 проходят). Шейдер SIMD32 собирается с 1131 сбросом и 2319 загрузками регистров (SIMD8 и SIMD16 — без сбросов): вероятна ошибка пути сбросов ELK или scratch-памяти при таком объёме. Не исправлено. |

Исправлено 2026-11-20: `glsl.builtin.precision.{sin,cos}.*` (8 отказов) — математический блок
Broadwell возвращает sin/cos чуть больше 1 по модулю (`sin(1.58)` = `0x1.0001a8p0`), CTS
требует [−1, 1]. Включён обход компилятора `precise_trig` (умножение на 0,99997, как в brw
для всех поколений до Gfx10, кроме KBL); `INTEL_PRECISE_TRIG=0` отключает.

## Законно неподдерживаемое (NotSupported)

| Группа | Причина |
|---|---|
| `api.copy_and_blit.multiplanar_xfer.*` | Нужна отдельная transfer-очередь; у HasVK (и у этого ICD) одна очередь графики и compute. |
| `image.texel_view_compatible.*.3d_image.*` для сжатых форматов | Несжатый вид сжатого изображения Gen8 описывает только для одного слоя (`isl_surf_get_uncompressed_surf` до Gfx9), а вид 3D-изображения всегда охватывает все срезы глубины. Upstream HasVK объявлял поддержку и падал на `assert` (без них — access violation на неинициализированной поверхности); порт сообщает `VK_ERROR_FORMAT_NOT_SUPPORTED` для 3D + сжатый формат + `BLOCK_TEXEL_VIEW_COMPATIBLE` (с 2026-11-20; было 68 падений на каждом 6-м случае группы). |
| Расширения только для Linux | dma-buf, DRM-модификаторы, fd-дескрипторы памяти и семафоров, `pci_bus_info`, `queue_family_foreign`. |
