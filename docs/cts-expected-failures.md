# Ожидаемые отказы и неподдерживаемые группы CTS

Конфигурация: Iris 6100 (8086:162b), драйвер `20.19.15.5171`, Windows, CTS
`vulkan-cts-1.4.5.5`. В списке — только отказы с установленной причиной,
которую нельзя или не нужно устранять в ICD.

## Отказы

| Тест | Результат | Причина |
|---|---|---|
| `dEQP-VK.tessellation.misc_draw.tess_factor_barrier_bug` | `VK_ERROR_DEVICE_LOST` через ~4 с (иногда Pass) | Нагрузка дольше таймаута TDR Windows (2 с), а не зависание. Вершинный шейдер делает ≈6,0·10⁸ `atomicAdd` в одну ячейку (524 288 инстансов × 4 вершины × 36/64 × 512). Измеренная скорость атомиков в один адрес на этой GPU — 287 млн/с (compute, счётчик точный), то есть ≥2,1 с только на атомики. В Linux у i915 нет жёсткого 2-секундного лимита, поэтому upstream этот тест проходит. Менять `TdrDelay` — системная настройка, ICD её не трогает. |
| Следующий за ним тест в том же процессе | `ResourceError` | Устройство потеряно предыдущим тестом; отдельно этот тест проходит. |
| `dEQP-VK.wsi.win32.swapchain.simulate_oom.min_image_count` | `Timeout` (и при лимите 20 мин) | Долгий тест, не ошибка: для 16 конфигураций (1–16 изображений) он отказывает каждому выделению по очереди, около 2300 попыток создать swapchain. Каждая стоит ~0,5 с: изображения и их CPU-буферы — отдельные выделения WDDM. Все 16 конфигураций пройдены без падений и ошибок. |

## Законно неподдерживаемое (NotSupported)

| Группа | Причина |
|---|---|
| `api.copy_and_blit.multiplanar_xfer.*` | Нужна отдельная transfer-очередь; у HasVK (и у этого ICD) одна очередь графики и compute. |
| Расширения только для Linux | dma-buf, DRM-модификаторы, fd-дескрипторы памяти и семафоров, `pci_bus_info`, `queue_family_foreign`. |
